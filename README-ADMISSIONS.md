# 观澜 · 研途雷达

当前首页入口是 `src/grad-main.tsx`，保留之前科研实践页的布局和 `research.css` 样式。
`src/admissions-main.tsx` 是保留的通知工作台实现，不作为当前首页；
旧新闻数据、API 和源码保留，不进入招生资料空间。新表均以 `grad_` 开头。

## 启动

Windows：运行项目根目录的 `打开研途雷达.cmd` 或 `start-background.ps1`，成功后访问 `http://127.0.0.1:4321/`。
关闭终端不关闭该后台服务。仅本机绑定，无账户，禁止直接开放公网。
通用方式：Node 24+，`pnpm install`、`pnpm build`，设置 `PORT=4321` 后 `pnpm start`。
本机启动脚本使用根目录 `guanlan.sqlite`（如存在），否则使用 `data/guanlan.sqlite`。

## 功能

- 机会雷达：后端标题/学校/专业检索、阶段、地区、入学年、日期状态筛选。
- 学生画像：专业、地区、目标院校、入学年及简单资格条件，本地持久化。
- 条件核对：明确符合 / 明确不符 / 需要核实。仅支持已结构化的简单条件；真实正文中的复杂条件保留人工核验，不能推断录取概率。
- 官方证据：原文链接、字段摘录、采集时间、独立年份；缺失值不猜测。
- 人工纠正：截止日期、阶段、活动年、入学年与依据；独立覆盖层保留原始通知，原文变化后暂停旧核验。
- 目标清单、申请状态、材料勾选、手动任务、准备笔记。
- 日历与 ICS 导出、申请简报与 Markdown 导出、浏览器打印 PDF。
- 通知字段版本对比；首次采集不伪造变化。
- 手机主从布局、浅色/深色外观、空态/错误态、未保存提示。

## 当前覆盖与边界

学校研究资料：输入学校名，确认 `.edu.cn` HTTPS 官方主页后选择专业/方向。
如需自动发现此前未登记学校的官网及相关院系、实验室、课题、教师候选，
在启动服务的**同一终端环境**设置 `BRAVE_SEARCH_API_KEY`。密钥只在后端使用。
未配置时仍可登记学校并输入其官方网页链接，或查阅已缓存资料；
系统不会把搜索摘要当作证据。对已知北大、清华，登记 `www` 主页后允许读取其官方子域名。
采集要求域名匹配、公开 DNS 地址、robots 允许、超时与大小限制；
失败保留已有索引，五分钟内同一检索复用缓存。页面标题和内容通过规则归类，
需要人工核对，绝不据教师主页声称本年度招收推免生。
目前只把每页与学校关联；院系—实验室—导师间从属关系尚无可验证证据模型，
详情明确显示待核实。自动检索依赖搜索服务返回的候选页面，也不保证覆盖全部师资。
学校登记是本机用户确认而非院校认证；不支持非 `.edu.cn` 官网。
目标状态、联系笔记和通知申请记录持久化在 SQLite 中；本机单用户模式禁止直接公网部署。

首批实际接入：北京大学计算机学院、清华大学计算机系招生栏目。
每个来源单次读取首屏候选中的至多 6 份正文；不是 20 校、全校或全网覆盖。
只保留通知元数据、必要证据片段与结构化结果；不登录、不报名、不执行来源脚本。
只请求固定官方白名单，同源重定向、robots 检查、12 秒超时、2 MB 上限。
手动更新，五分钟缓存，失败保留缓存；解析版本升级会重新验证。
PDF 附件及图片内条件未提取，不把空正文条件判定为符合。
目前没有持续后台监控、邮箱/微信推送或多用户协作。
日期识别保守：没有明确年份/多个候选截止时间时留空，支持人工纠正。
演示空间为六个虚构院校机会，使用 example.com，明确标识并完全隔离。
来源可访问与 robots 允许不等于再分发授权；参赛材料需另外核实来源及许可证。

## 验证

- `pnpm test`：旧版回归测试与保研模块测试。
- `pnpm build`：类型检查与生产构建。
- `node tests/browser-admissions.mjs`：本机 Edge 自动化，使用捆绑 Playwright 的路径；其他电脑须调整依赖路径。
- 浏览器测试只在演示空间填写画像、创建申请，不污染正式申请记录。
- `screenshots/` 保存桌面、手机实机截图及 `qa-result.json`。

## 设计与开发披露

使用本机 `design-taste-frontend` skill 的审计、设计读取、色彩/字体/可访问性原则。
该 skill 明确不针对仪表盘，因此没有套用其营销页模板、照片 Hero、社交背书或定价版式。
采用现有 React / Lucide / 原生 CSS，青绿主操作色，状态色独立，浅色默认并可切换深色。
设计参数：DESIGN_VARIANCE=4 / MOTION_INTENSITY=2 / VISUAL_DENSITY=5。
AI 辅助了实现和测试编写；不声称纯人工逐行开发。参赛前应按实际情况补充工具/模型、人工审核、团队分工与测试过程。
本成果是可运行原型，不保证任何竞赛奖项。
