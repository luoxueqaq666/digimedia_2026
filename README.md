# 观澜 · 保研信息工作台（本地原型）

当前入口是四个独立页面：首页搜索学校并按本科专业和研究方向排序学院；资讯公告核对曾搜索学校的学院招生栏目；申请计划整理报名截止、活动日期、材料、官方链接及个人参与/录取状态；导师方向按关键词联网检索导师并展示逐字段原文依据、方向匹配和个人笔记。个人资料与记录保存在本机 SQLite。

**按关键词找导师的流程：** 三个页面共用同一个「学校检索」控件（`src/SchoolPicker.tsx`）：输入学校名称即列出已核验目录，点「检索学校」用搜索接口核对官方域名后登记；在首页搜索过的学校会自动标记为「已关注」，资讯公告页可以随时切换或取消关注。导师页把学校、可选学院、研究方向关键词一起提交给 `POST /api/grad/research/mentors`，后端校验并拆分关键词（支持中英文顿号、逗号、分号、空格，单个不超过 60 字、最多 12 个），用受控同义词表扩展成检索式（例如“计算机视觉 / computer vision”），再用搜索接口（默认 DeepSeek 联网搜索，可切换 Brave）限定到该校官方域名发现候选链接。搜索摘要只用于发现链接；每个候选页面都会被重新读取，用 Cheerio 规则解析（不同学校可注册独立适配器）后才可能成为结果。

**不检索的情况：** 学校尚未核验官方来源、也没有已接入的学院目录时，后端直接返回说明而不发起任何网络检索；界面改为提示先接入官方来源，或直接把官方教师主页链接贴进「补充官方页面链接」。已登记官方域名但缺乏学院目录的学校，可以在界面上「发现官方教师目录」：后端在该校官方域名内检索师资栏目页，逐页重新读取并统计教师链接，只把合格页面（≥4 个教师链接且出现师资栏目词）作为候选保存；用它检索时仍会逐位读取原文核对，界面标注「该目录来自搜索发现，尚未逐页核验」。搜索受限域名之外的候选链接会被丢弃并在状态行显示数量，https 读取失败的官方站点会按 http 回退一次，整轮抓取有 25 秒上限（目录发现为每页 8 秒、最多 6 页），超时的页面如实标记为“本轮未读完”。

**来源清单与资料缺口：** 导师页顶部列出该校本轮全部可用来源，逐条标明是「学院官方师资目录」还是「搜索发现并复核的官方目录」，并显示该目录的官方 URL。点任意一条即以该来源重新检索。内置目录里没有配置师资目录的学院会显示为“资料缺口”（例如“信息科学技术学院 尚无已核验的官方教师目录”），这些学院的教师不会被列出，也不会用搜索摘要补齐。学校与学院的对应关系只来自内置目录记录和已保存的官方目录页本身，不从搜索摘要推断。

**官方招生栏目发现：** 已登记或已关注的学校若还没有官方招生栏目，可在资讯公告页点对应学校标签上的「发现官方招生栏目」。后端在该校**已核验域名**内检索招生栏目页（4 条带 `site:` 的检索式），逐页重新读取后判定：页面需同时出现「研究生招生/推免/夏令营」等栏目词和可核验的通知链接，才作为栏目保存。提交的域名与已核验域名不一致时直接拒绝（防止把甲校域名套到乙校）。采集遵守域名白名单、`robots.txt`、8 秒超时与按天缓存；名单/公示/录取结果类标题和站外链接一律丢弃。勾选通知后点「读取正文并导入所选通知」，正文会重新读取并按规则提取字段。栏目页与通知标题里的年份用于区分**当年通知**与**历史通知**（`recency`），年份无法判定时标为未知，不猜测。

**字段提取与人工核验：** 报名截止、活动日期、申请材料、申请条件分别提取，每项都带原文依据（`deadlineEvidence`、`materials[].evidence`、`requirements[].evidence`）和官方链接。规则如下：活动日期只从「举办/开营/报到/活动时间」子句读取，报名与申请时间段不会被当成活动日期；“报名时间 A 至 B”只把 B 当截止日期；同一通知出现多个不同截止日期、只写月日没有年份、或完全没有日期时，一律保持 `null` 并显示「待核验」。材料清单句（“提交/上传…成绩单”）不会拼进申请条件。申请计划页每一行可点「人工核验」修正阶段、截止日期、活动日期、材料与申请条件，必须填写至少 8 字的官方原文依据；修正是本机记录，重启后保留，原文内容变化时会自动暂停生效并提示重新核对。

**排序：** 只以本次关键词命中研究方向的强度为准，个人背景仅作辅助，不覆盖本次输入意图。仅当页面可读且非空时才收录；未公开字段保持空白，不按姓名推断邮箱。

**覆盖边界：** 内置目录目前只有中国科学技术大学：已核验计算机科学与技术学院的教师目录（正高级教授栏目，非全校导师名册）和招生工作栏目，信息科学技术学院仅有官方学院入口及通知栏目。其他学校需要先在「学校检索」中核对并登记官方域名，之后按关键词检索限定在该域名内；没有搜索密钥时只能读取已接入学校的师资目录，覆盖范围有限，界面会直接提示“不能称为全网搜索”。**界面不会声称全校覆盖**：`coverageGaps` 会明确列出还有哪些学院没有已核验的官方教师目录。部分主页平台（如 faculty.xxx.edu.cn 模板）的研究方向与联系方式由脚本加载或做了混淆：研究方向常放在面包屑标注的栏目页正文里（已支持按「当前位置: … >>研究方向」读取），但邮箱做了 SHA-256 混淆的页面只能读到姓名与职称，其余字段保持空白。研究方向不代表当年招生名额。

**公告覆盖面：** 资讯公告与申请计划覆盖**全部已关注学校**，不再只依赖当前选中的学校。每所学校单独显示数据状态标签（读取中 / N 条公告 / 暂无已核验栏目 / 读取失败原因），某一所接口失败只影响该校标签，其它学校照常显示并保留上次成功资料。点「更新官方栏目」会并发刷新所有已关注学校，失败数量会在状态行说明。

**联系方式归属：** 邮箱和办公电话只从本人页面的公开文本或 `mailto:` 链接读取；学院公共邮箱、招生秘书、学生联系人和公共电话会被排除，判定不了就留空。

官方公告可能是往期活动；发布日期不是报名截止。没有明确截止日期时保持“待官方核验”。材料和申请要求为规则提取，需核对官方原文；“参与/录取”是用户个人记录，不是学校报名或录取结果。五分钟缓存、离线保留成功快照，只有用户打开相关页或手动刷新时读取官方栏目。导师检索另有 SQLite 缓存：同一学校＋学院＋关键词十分钟内直接复用缓存结果，断网时显示上次成功结果或本机已保存资料，并明确标注“缓存/断网缓存”，不会用摘要补位。

Windows 运行 `start-background.ps1`，访问 `http://127.0.0.1:4321/`。修改前端后运行 `npm run build` 并刷新浏览器。需要 Node.js 24+。搜索密钥放在项目根目录 `.env`（`SEARCH_PROVIDER=deepseek` + `DEEPSEEK_API_KEY`，或 `SEARCH_PROVIDER=brave` + `BRAVE_SEARCH_API_KEY`）；`.env` 只在后端启动时读取，改完必须重启后端。DeepSeek 调用为 `POST https://api.deepseek.com/anthropic/v1/messages`，模型取 `DEEPSEEK_SEARCH_MODEL`（默认 `deepseek-v4-flash`），工具为原生 `web_search_20250305`（`max_uses: 2`）；密钥只放在 `x-api-key` 请求头，任何错误信息都不会回显密钥或上游正文，返回的生成文字不会被当成搜索结果。验证用 `npm test`、`node tests/browser-grad.mjs`、`node tests/browser-mentor.mjs`、`node tests/browser-school-flow.mjs`、`node tests/browser-directory-flow.mjs`、`node tests/browser-pages.mjs`（四个页面 × 桌面/手机）、`node tests/browser-sections.mjs`（真实网络栏目发现）；离线缓存用例 `node tests/browser-mentor-offline.mjs` 会临时停掉 4321 端口的服务，需手动重启；截图位于 `screenshots/grad/`。本地登记过的学校会留在 `grad_schools` 与「已关注」列表里，可在资讯公告页点标签上的「×」逐个移除。

## 旧版选题研究工作台

本地可交互软件原型：公开报告导入、候选事件聚合、来源对比、采集历史、选题笔记和带出处的简报。与 `news.buchuo.cloud` 独立，不修改其服务。

## 运行

需要 Node.js 24 或更高版本、pnpm。

```sh
pnpm install
pnpm build
pnpm start
```

默认监听 `http://127.0.0.1:4317`，端口被占用时依次尝试至 4330。仅允许本机访问。开发运行使用 `pnpm dev`。

Windows 本机已提供 `start-local.ps1`，可以从任意目录运行。默认使用此机器的捆绑 Node.js。若改用自己的运行环境，执行上面的通用命令。

## 数据

- 默认显示真实资料。点击“刷新公开报告”获取原站公开 HTML；不会自动定时抓取。
- 五分钟缓存包含失败请求，重复点击不会持续请求原站。请求超时为 15 秒、响应上限 5 MB。
- `data/guanlan.sqlite` 保存原始链接、报道、快照、事件分组、收藏、选题与笔记。SQLite 的 WAL/SHM 是正常辅助文件。
- 仅收录标题和来源，不抓取全文、不登录后台、不调用付费 AI。
- 排名区间如 `1-10` 只显示原文，不推断当前排名。只有同一报道至少两个明确单次排名才绘制历史；来源覆盖柱状图使用真实快照。
- 原站时间为原样记录，可能缺少年份或时区，不冒充精确发布时间。筛选日期基于本地采集时间。
- 演示数据隔离在 `dataset=demo`，虚构标题和历史一并标注，链接指向 example.com。不得作为真实研究证据。
- 以规范化 URL 去重，清理常见追踪参数；二元字符 Dice 相似度 >= 0.64 形成候选事件。不是语义模型或事实核查。人工合并和拆分之后的分组不会被重导入覆盖。

## 主要接口

所有数据接口接受 `dataset=live|demo`（默认 live）。无认证，因而禁止远程部署；包含 Host 和跨 Origin 请求检查。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/summary` | 来源、主题、缓存时间、导入状态 |
| GET | `/api/events?q=&topic=&source=&since=&sort=&starred=` | 后端筛选候选事件 |
| GET | `/api/reports` | 当前数据集原始报道 |
| GET | `/api/events/:id/history` | 各次采集记录 |
| PATCH | `/api/events/:id/star` | `starred: boolean` |
| POST | `/api/events/:id/merge` | `sourceId`，并入当前事件 |
| POST | `/api/events/:id/split` | `reportId`，拆出单条报道 |
| POST | `/api/refresh` | 手动读取固定原站，不接受任意远程 URL |
| GET/POST | `/api/pitches` | 列表 / 新建 |
| PUT | `/api/pitches/:id` | 保存全部编辑字段与 `reportIds` |
| GET | `/api/pitches/:id/brief?format=md` | JSON 或 Markdown 附件 |

导师检索相关接口（`/api/grad` 前缀）：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/grad/catalog/schools?q=` | 学校检索：内置目录＋已登记学校，带 `collegeCount` / `known` / `registered` |
| GET | `/api/grad/catalog/history` | 已关注学校（含内置目录与已登记学校） |
| POST | `/api/grad/catalog/history` | `{ school }`，关注一所已收录或已登记的学校 |
| DELETE | `/api/grad/catalog/history?school=` | 取消关注 |
| GET | `/api/grad/research/school-candidates?q=` | 用搜索接口核对学校官方域名候选 |
| POST | `/api/grad/research/schools` | `{ name, url }`，登记 `.edu.cn` 官方主页 |
| POST | `/api/grad/research/school-directories` | `{ schoolId, school, host }`，在该校官方域名内发现并保存官方教师目录页 |
| POST | `/api/grad/research/school-sections` | `{ schoolId?, school }`，在该校已核验域名内发现并保存官方招生栏目；域名与登记记录不一致时拒绝 |
| POST | `/api/grad/research/section-import` | `{ school, urls? }`，只接受已保存栏目页里的通知链接，逐条重读正文提取字段 |
| GET | `/api/grad/catalog/school-notices?school=` | 单校公告：始终返回数组并带 `known`/`registered`/`skipped`，学院目录缺失不算失败 |
| POST | `/api/grad/research/mentors` | `{ school, host, college?, keywords, profile?, urls?, directory?, requireSource? }`，联网检索并按原文排序；返回 `collegeOptions` 与 `coverageGaps` |
| GET | `/api/grad/research/mentors?school=` | 本机已保存的教师资料（逐字段来源随结果返回） |

选题字段：title、background、angle、questions、notes、status、reportIds。状态仅为待研究、整理中、已完成。选题不能跨数据集关联报道。

## 验证与边界

```sh
pnpm test
pnpm build
```

测试涵盖解析、URL 安全、去重、快照、数据隔离、人工分组、持久化、筛选、缓存、离线、导出和跨源请求。浏览器验收记录见 `QA.md`。

本原型不包含用户账户、协作、推送、模型事实核查。简报内容由用户填写，模板生成并非 AI 生成。上线前还需权限、安全审查、部署配置、备份策略与数据授权核实。参赛资格和原项目获奖历史应向组委会确认。
